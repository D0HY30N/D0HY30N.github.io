> 블로그의 카테고리와 본문 모양을 확인하기 위한 예시 글입니다.

웹 페이지를 열면 브라우저는 여러 요청을 보냅니다. 처음부터 모든 헤더를 외우기보다, 요청 하나를 골라 **무엇을 요청했고 어떤 응답을 받았는지** 살펴보면 흐름을 이해하기 쉽습니다.

## 메서드와 경로부터 보기

다음은 학습용으로 단순화한 HTTP/1.1 요청입니다.

```http
GET /notes?category=web HTTP/1.1
Host: example.com
Accept: application/json
```

`GET`은 요청 메서드이고, `/notes`는 요청한 경로입니다. 물음표 뒤의 `category=web`은 쿼리 문자열입니다. 이 예시에서는 WEB 분류의 노트를 조회하려는 요청으로 해석할 수 있습니다.

| 항목 | 확인할 내용 |
| --- | --- |
| 메서드 | 어떤 동작을 요청하는가? |
| 경로와 쿼리 | 어느 자원에 어떤 조건으로 접근하는가? |
| 헤더 | 요청에 어떤 부가 정보가 담겨 있는가? |
| 본문 | 전송하는 데이터가 있는가? |

## 응답과 연결해서 읽기

요청만으로는 실제 결과를 알 수 없습니다. 상태 코드와 응답 헤더, 본문을 함께 확인합니다.

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"notes": [{"title": "HTTP 학습 기록"}]}
```

위 응답에서는 성공 상태와 JSON 형식의 결과를 확인할 수 있습니다. 요청에서 보낸 조건이 실제 결과에도 반영되었는지는 응답 본문까지 읽어 판단합니다.

## 짧게 기록하기

- 요청의 목적을 한 문장으로 적습니다.
- 예상한 응답과 실제 응답을 비교합니다.
- 이해하지 못한 헤더는 이름과 궁금한 점을 함께 남깁니다.

처음에는 작은 요청 하나를 끝까지 읽는 것만으로도 충분합니다. 같은 형식으로 기록을 쌓으면 비슷한 요청을 만났을 때 비교하기 편해집니다.
